# Формы и серверный каталог

Сайт собирается статически, а `/sendOrder.php`, `/send-question.php` и `/submit.php` исполняются PHP на веб-сервере. Astro dev/preview PHP не исполняют.

Обратная связь («Задать вопрос») направляется на `nt@tech-new.ru`, заказы — на `tendernt@tech-new.ru`. Получатели предложений поставщиков перечислены отдельно в `public/submit.php`. Эти адреса задаются в коде обработчиков и не принимаются из запроса браузера.

После успешной отправки заявки менеджеру покупателю отправляется отдельное письмо: номер заявки, состав, количество, цены и итог из серверного каталога. Reply-To этого письма — `tendernt@tech-new.ru`. Ошибка отправки копии не отменяет уже принятую заявку: ответ сохраняет `success: true` и номер, но возвращает `confirmationSent: false`, а интерфейс предлагает сохранить номер. Поставщикам по закупкам и авторам вопросов автоматические письма-подтверждения не отправляются; принятие показывается в форме.

## Развёртывание

1. Нужен 64-битный PHP 8.1+ с расширениями Fileinfo и Zip. Настройте доставку `mail()` от `no-reply@tech-new.ru`. Дополнительные библиотеки PHP для чтения Excel не нужны.
2. Выполните `npm ci` и `npm run build`. Загружайте содержимое `dist/` целиком, включая `_forms/bootstrap.php`, `_forms/orders.php`, `_forms/.htaccess`, `procurement.xlsx`, `server-data/order-catalog.json`, `.htaccess` и `.user.ini`. Composer и Node.js на хостинге не нужны. Если остались файлы прежней версии, после обновления можно удалить `_forms/excel.phar`, `_forms/procurement.php` и `_forms/vendor/`. Саму `_forms/` удалять нельзя: общие обработчики форм по-прежнему нужны.
3. При изменении цен пересоберите сайт: сервер использует каталог из той же сборки. Идентификатор позиции включает её исходный ID, название и цену, поскольку ID в исходных списках пересекаются. Позиция со старой ценой отклоняется с просьбой обновить корзину; переданные браузером название и цена не используются.
4. Укажите `FORM_PRIVATE_DIR` — абсолютный путь к каталогу **вне document root**, доступному PHP для записи. Например, `/var/lib/ruastro/forms`. Если переменная не задана, используется отдельный каталог приложения в системной временной папке. Размещение внутри публичного каталога запрещено кодом.
5. Проверьте тестовую заявку на своём хостинге и доставку писем. Ответ `mail() = true` означает приём письма почтовой системой, а не подтверждённую доставку адресату.

Логи содержат только внутренний номер, время, статус отправки и количество позиций/файлов. Контакты и текст заявки в файловые логи не записываются. Журналы разбиты по месяцам, файлы старше 90 дней удаляются при поступлении заявки. Для постоянного хранения выбирайте отдельный каталог, а не системную временную папку.

В `FORM_PRIVATE_DIR/orders/` сохраняются записи защиты от повторной отправки: хеш запроса, номер, состояние обработки и результат без контактов и состава заказа. Браузер повторяет сетевой запрос с тем же UUID, в том числе после перезагрузки страницы; уже завершённый запрос получает прежний результат без писем. Каталог проверяется до перехода в `pending`: после временной ошибки каталога запрос можно повторить. Готовый результат возвращается из записи даже при последующей недоступности каталога. После явного отказа почтовой системы повтор разрешён. Если процесс прервался во время отправки и результат неизвестен, сервер сохраняет состояние `pending` и предлагает уточнить статус по номеру у менеджера вместо повторной рассылки. Записи заменяются атомарно под блокировкой. Они не удаляются автоматически; сохраняйте этот каталог при обновлении сайта и используйте постоянный `FORM_PRIVATE_DIR`. Браузер хранит только UUID и хеш, без контактов. После успеха из корзины вычитаются отправленные количества; добавленные позже товары сохраняются. Удалённая и заново добавленная позиция получает новую локальную метку, поэтому старый ответ её не удаляет.

SheetJS CE для списка закупок и проверки шаблона в браузере остаётся на версии 0.20.3; официальный архив находится в `vendor/`, контрольная сумма указана в `vendor/README.md`. Сервер не читает значения ячеек Excel и не использует PhpSpreadsheet, PHAR или Composer. Содержимое предложения проверяет сотрудник после получения письма.

Старые `form-submissions.log` и `order-submissions.log`, оставшиеся от прошлых версий на хостинге, нужно перенести из document root или удалить. В Apache 2.4 добавленные `.htaccess` закрывают HTTP-доступ к `.log`, `.ini`, `_forms/` и `server-data/`. Убедитесь, что разрешён `AllowOverride`.

Для Nginx добавьте в существующий `server` (до общих обработчиков):

```nginx
location ^~ /_forms/ { deny all; }
location ^~ /server-data/ { deny all; }
location ~* \.(?:log|ini)$ { deny all; }
client_max_body_size 13m;
```

Не направляйте запросы к PHP в статический файловый сервер: обработчики должны исполняться, а не скачиваться как текст.

## Ограничения

- До 3 МБ на файл и до 12 МБ на все шесть вложений. `upload_max_filesize=3M`, `post_max_size=13M`, `max_file_uploads=6`; `.user.ini` задаёт эти значения для поддерживающих её CGI/FastCGI-хостингов. Для mod_php задайте их в конфигурации PHP.
- Документы компании: PDF, DOC, DOCX, JPG, PNG; счёт: PDF; предложение: XLSX или XLS. Проверяются размер, расширение, MIME по содержимому и структура Office-контейнера. XLSX/DOCX с макросами, зашифрованными элементами или встроенными исполняемыми файлами отклоняются. Файлы не сохраняются на сайт: PHP удаляет временные загрузки по завершении запроса. Проверка формата не заменяет антивирусную проверку вложений на почтовом сервере.
- До 10 обращений на IP и обработчик за 15 минут. `FORM_RATE_LIMIT` позволяет задать другое значение в диапазоне 1–1000. Используется `REMOTE_ADDR`; за reverse proxy настройте передачу клиентского IP на веб-сервере, не доверяя произвольному `X-Forwarded-For`.
- Для предложения сохраняется обязательный номер выбранного лота и проверка формата XLS/XLSX. Сервер не проверяет столбцы, строки, цены, суммы, сроки поставки или соответствие позиций списку закупок. Номер лота передаётся сотрудникам в теме и тексте письма. Проверка шаблона в браузере сохранена.
- По умолчанию разрешены Origin `https://tech-new.ru` и `https://www.tech-new.ru`. Дополнительные точные Origin можно перечислить через запятую в `FORM_ALLOWED_ORIGINS`. Запросы без Origin допускаются, но тоже валидируются и ограничиваются по частоте. CORS `*` не используется.
- Контакты проверяются на сервере, включая тип, длину, формат email/телефона и обязательные согласия. В заказе допускается 1–100 позиций и 1–999 штук одного товара; цена рассчитывается целыми копейками. Корзина не разрешает добавлять 101-ю позицию и показывает сообщение об ограничении. Для старых сохранённых корзин лимит дополнительно проверяется перед отправкой формы.

## Проверка

```sh
npm run build
npm test
```

Для HTTP-тестов нужен `php` в PATH либо переменная `PHP_BINARY` с путём к исполняемому файлу. При необходимости `PHP_CONFIG` задаёт путь к тестовому `php.ini` с Fileinfo и Zip. Тесты запускают отдельный PHP-сервер на случайном локальном порту и подменяют почтовую функцию через `tests/forms/mail-stub.php`; реальные письма не отправляются. Каталог и PHP-обработчики тестируются из `dist/`, поэтому перед тестами требуется сборка.

Dev-сервер и сборка используют разные каталоги кэша Vite, чтобы сборка не ломала загрузку модулей в уже открытой вкладке localhost.
